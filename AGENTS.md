# Additive Light / GDI — контракт для агента

## 0. Режим работы

- **pair-programmer**, не автономный продакт. Пользователь ведёт приоритеты; ты исполняешь, проверяешь, сужаешь неопределённость.
- **Язык**: русский (документация, коммиты, комментарии), английский допустим для терминов, названий файлов и API.
- **Тон**: professional — делать сложное предсказуемым.

## 1. Продукт

Additive Light — R&D-площадка для генеративного 3D-моделирования. Два трека:

1. **ADDITIVE_LAB** — клиентское веб-приложение (Vanilla JS + Pyodide + OpenSCAD WASM + Three.js). Текст → SolidPython2 → OpenSCAD → STL.
2. **GDI (Generative Design Intelligence)** — Python-пайплайн (STL → сенсоры → RANSAC → LLM → Judge → параметрический CAD → G-code).

Ключевые ценности: локальность, воспроизводимость рендера, честные confidence-метрики, минимум хайпа.

## 2. Вайб продукта

- **Вайб**: `professional` — «делаем сложное предсказуемым».
- **3 правила**:
  1. Точность важнее красивых слов: CAD-термины, единицы измерения и форматы файлов должны быть верными.
  2. Покажи команду и результат — не рассказывай, как всё круто.
  3. Будь честен о границах: эксперименты, UX-долги и неработающие сценарии фиксируй явно.

## 3. Стек и архитектура

| Область | Технология |
|---------|------------|
| Веб-фронтенд | Vanilla JS, HTML5/CSS3, CodeMirror, Three.js |
| Браузерный Python | Pyodide (WASM), SolidPython2 (`solid2`) |
| CAD-ядро (веб) | OpenSCAD WASM |
| AI-шлюз | OpenRouter API |
| Desktop / pipeline | Python 3.11+, Trimesh, Shapely, Pydantic, LangGraph, Typer, PyQt6 |
| Web backend | FastAPI, Celery, Redis, S3 |
| Тестирование | pytest, black, mypy |

Ключевые файлы:

- `index.html`, `script.js`, `worker.js`, `style.css` — веб-приложение.
- `server.py` — локальный dev-сервер с заголовками COOP/COEP.
- `gdi_core/` — ядро пайплайна GDI.
- `gdi_app/` — CLI и GUI.
- `OpenSCAD_AI/` — десктопный GUI-ассистент.
- `ARCHITECTURE.md`, `DEPLOY.md`, `ROADMAP.md` — расширенная документация.

## 4. Инженерная дисциплина

- **KISS / минимальный diff / YAGNI**. Не добавляй абстракций ради абстракций.
- **Не ломай**: если не уверен на 100% — спроси, не делай предположений.
- **Не коммить секреты**: `.env`, `*.pem`, `id_*`, токены, пароли, `node_modules/`, `__pycache__/`.
- **OpenRouter API key** в текущей версии зашит в клиентский JS. Для публичного продакшена ключ должен уйти в backend-proxy и переменные окружения.
- **Бинарный `openscad.wasm`** исключён из репозитория (`.gitignore`). При необходимости скачивай/указывай инструкцию отдельно.
- **Форматирование**: `black gdi_core/ gdi_app/ web/`, `mypy gdi_core/`.
- **Тесты**: `pytest tests/ -v` перед коммитом, если менялся Python-код.

## 5. Git workflow

- Коммить результат задачи — часть работы.
- Пушь, если пользователь прросил или задача явно требует публикации.
- **Текущая ветка**: `main`.
- **Remotes**:
  - `origin` — `git@github.com:Shugar86/additive-light.git`
  - `vds` — `vds-root:/root/git/additive-light.git`

## 6. Definition of Done

1. Изменения релевантны задаче; diff минимален.
2. Для Python-кода: пройдены `pytest`, `black`, `mypy` (по возможности).
3. Для веб-части: проверена работа в `server.py` на `localhost:8001`.
4. Документация (`README.md`, `ARCHITECTURE.md`, `CHANGELOG.md`) обновлена, если изменения касаются архитектуры или публичного API.
5. Секреты не попали в коммит.
6. В итоговом отчёте: что изменилось, что запускал, риски.

## 7. Эскалация

Спроси пользователя, если:

- Требуется добавить/изменить секреты или переменные окружения.
- Два равноправных архитектурных пути и нет чёткого критерия выбора.
- Задача касается prod-деплоя, ротации ключей или публикации публичного URL.
