# Additive Light / GDI — контракт для агента

**Версия:** 2.0 · **Вайб:** professional — инженерная точность в генеративном 3D

---

## 0. Режим работы

- **pair-programmer**, не автономный продакт. Пользователь задаёт приоритеты; агент исполняет, проверяет и сужает неопределённость.
- **Язык**: русский для документации, коммитов и комментариев; английский допустим для терминов, имён файлов, API и кода.
- **Тон**: professional — спокойный, точный, без хайпа. Делаем сложное предсказуемым.

---

## 1. Продукт

Additive Light — R&D-площадка для генеративного 3D-моделирования и обратного инжиниринга сканов. Два трека:

1. **ADDITIVE_LAB** — клиентское веб-приложение (Vanilla JS + Pyodide + OpenSCAD WASM + Three.js). Текст → SolidPython2 → OpenSCAD → STL.
2. **GDI (Generative Design Intelligence)** — Python-пайплайн (STL → сенсоры → RANSAC → LLM → Judge → параметрический CAD → G-code).

Ключевые ценности: локальность, воспроизводимость рендера, честные confidence-метрики, минимум абстракций.

## 3. Стек и архитектура

| Область | Технология | Назначение |
|---------|------------|------------|
| Веб-фронтенд | Vanilla JS, HTML5/CSS3, CodeMirror, Three.js | UI, редактор, 3D-вьювер |
| Браузерный Python | Pyodide (WASM), SolidPython2 (`solid2`) | Исполнение AI-кода в браузере |
| CAD-ядро (веб) | OpenSCAD WASM | CSG-рендеринг и экспорт STL |
| AI-шлюз | OpenRouter API | Доступ к coder-моделям |
| Desktop / pipeline | Python 3.11+, Trimesh, Shapely, Pydantic, LangGraph, Typer, PyQt6 | Скан → CAD pipeline |
| Web backend | FastAPI, Celery, Redis, S3 (Phase 2) | Масштабируемое API |
| Тестирование | pytest, black, mypy | Качество и консистентность |

Ключевые файлы:

- `index.html`, `script.js`, `worker.js`, `style.css` — веб-приложение.
- `server.py` — локальный dev-сервер с заголовками COOP/COEP.
- `gdi_core/api.py` — публичный API ядра.
- `gdi_core/` — сенсоры, аппроксиматор, синтезатор, Judge, оптимизатор, модели.
- `gdi_app/` — CLI (`gdi_app/cli/main.py`) и GUI (`gdi_app/gui/`).
- `OpenSCAD_AI/` — десктопный GUI-ассистент.
- `ARCHITECTURE.md`, `DEPLOY.md`, `ROADMAP.md` — расширенная документация.

## 4. Инженерная дисциплина

- **KISS / минимальный diff / YAGNI.** Не добавляй абстракций ради абстракций.
- **Не ломай:** если не уверен на 100% — спроси, не делай предположений.
- **Не коммить секреты:** `.env`, `*.pem`, `id_*`, токены, пароли, `node_modules/`, `__pycache__/`.
- **OpenRouter API key:** в текущей веб-MVP ключ задан в клиентском `script.js`. Перед публичным продакшеном ключ обязан уйти в backend-прокси и переменные окружения.
- **Бинарный `openscad.wasm`** исключён из репозитория (`.gitignore`). При необходимости скачивай/указывай инструкцию отдельно.
- **Форматирование:** `black gdi_core/ gdi_app/ web/`, `mypy gdi_core/`.
- **Тесты:** `pytest tests/ -v` перед коммитом, если менялся Python-код.

## 6. Definition of Done

1. Изменения релевантны задаче; diff минимален.
2. Для Python-кода: пройдены `pytest`, `black`, `mypy` (по возможности).
3. Для веб-части: проверена работа в `server.py` на `http://localhost:8001`.
4. Документация (`README.md`, `ARCHITECTURE.md`, `CHANGELOG.md`, `AGENTS.md`) обновлена, если изменения касаются архитектуры или публичного API.
5. Секреты не попали в коммит.
6. В итоговом отчёте: что изменилось, что запускал, риски.
