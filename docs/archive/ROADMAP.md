## Вижн, идеи и инсайты для развития экосистемы OpenSCAD_AI + Additive Light

Этот документ собирает лучшие идеи из двух проектов:
- десктопный ассистент `OpenSCAD_AI` (GUI/CLI, генерация чистого OpenSCAD кода);
- веб‑генератор `additive-light` (SolidPython2 → OpenSCAD → STL → браузерный просмотрщик).

Цель — описать направления развития, которые дадут максимум пользы пользователю: **надёжное AI‑проектирование, удобный просмотр и предсказуемое управление сценой (включая скролл)**.

---

## 1. Единая философия AI‑генерации

- **Параметрический дизайн по умолчанию**
  - Всегда начинать код с блока параметров (размеры, толщины, шаги, допуски).
  - Для веб‑версии: одинаковый стиль параметров в SolidPython2 (Python‑переменные наверху) и в OpenSCAD (для экспорта/совместимости).
  - В `OpenSCAD_AI` это уже заложено в системный промпт — эту же идею стоит дотащить в веб‑промпты.

- **Строгий аутпут без "болтовни"**
  - В обоих проектах системные промпты должны явно требовать: **"только код, без markdown и объяснений"**.
  - Для веб‑версии уже сделано (SolidPython2), но стоит синхронизировать формулировки с десктопной версией, чтобы поведение моделей было единым независимо от интерфейса.

- **Валидность и устойчивость**
  - В веб‑версии уже есть: проверка синтаксиса Python через Pyodide, баланс скобок, проверка незакрытых строк.
  - Идея: аналогичные проверки можно добавить в CLI/GUI‑pipeline (например, пост‑валидатор OpenSCAD кода перед сохранением файла).

## 2. Стратегии моделирования (STYLES / MODES)

Идея из `gui_app.py`: **явный выбор стратегии генерации** сильно повышает качество результата. Это стоит перенести в веб‑версию как "режимы" AI.

- **2.1. Organic (Hull) — органические формы**
  - Описание стратегии:
    - Использовать **последовательный hull** (sequential hulling) по сечениям.
    - Генерировать 2D‑профили (круг/полигон) на разных высотах Z, затем объединять через `hull()`.
  - Применение:
    - Корпуса с плавными обводами, ручки, лодки, "бионические" формы.
  - Для веб‑версии:
    - Ввести режим `Organic (Hull)` в AI‑панели.
    - В system prompt для этого режима явно описывать паттерн: "define profile_2d(z), then hull() between slices".
    - В SolidPython2 использовать `hull()` и генерацию профилей в цикле.

- **2.2. Mechanical (CSG) — механика и детали**
  - Описание стратегии:
    - Базовый "кирпич" (bounding box), потом `difference()` для вырезания посадочных мест, отверстий, каналов.
    - `union()` для рёбер жёсткости, боссов, крепёжных ушей.
    - `minkowski()` только по прямому запросу (очень тяжёлый).
  - Применение:
    - Корпуса, кронштейны, адаптеры, "механика под печать".
  - Для веб‑версии:
    - Режим `Mechanical (CSG)` в UI.
    - В промпте явно прописывать шаги: "start from main block, then carve using difference, then add reinforcements".

- **2.3. Lathe (Rotate) — тела вращения**
  - Описание стратегии:
    - Список точек профиля `[ [x1,z1], [x2,z2], ... ]`.
    - `polygon(points=...)` + `rotate_extrude(...)`.
  - Применение:
    - Вазы, бутылки, шахматы, ручки, колёса.
  - Для веб‑версии:
    - Режим `Lathe (Rotate)` в AI‑панели.
    - В system prompt: "represent profile as 2D polyline and use rotate_extrude".
    - Хорошо сочетается с уже существующими пресетами "vase".

- **2.4. Реализация в веб‑UI**
  - В `additive-light` уже есть AI‑панель — туда добавить селектор стратегии (как в `gui_app.py`), но:
    - **Не ломать текущий workflow**: по умолчанию `Auto`.
    - Для каждой стратегии — подмешивать отдельный блок инструкций в system prompt, как сейчас делается в `OpenSCAD_AI`.
  - Документировать стратегии в README, чтобы человек понимал, чем они отличаются и когда какую выбирать.

## 3. Мультимодальность (референсы: картинки и PDF)

В десктоп‑версии уже есть:
- кнопка `Attach Image/PDF`;
- конвертация файла в base64 и передача в модель.

**Идеи для веб‑версии:**

- **3.1. Загрузка изображения в браузере**
  - UI: кнопка в AI‑панели "📎 Прикрепить референс".
  - Технически:
    - `input[type=file]` + чтение в `FileReader` → base64.
    - Передача base64 либо:
      - напрямую в OpenRouter (если выбран совместимый мультимодальный модель), либо
      - в отдельный backend‑прокси (если надо скрыть ключи или сделать предпре‑/пост‑обработку).

- **3.2. Поведение промпта**
  - Если есть картинка:
    - добавлять в system/user prompt мета‑инструкцию: "image describes the target object; replicate geometry parametrically, not pixel‑exact".
  - Приоритет: **сначала текстовое описание пользователя**, картинка — лишь уточнение формы.

- **3.3. Ограничения и UX**
  - Ясно обозначить пользователю: "Картинка — это референс. Модель будет параметрической, а не точной 3D‑реконструкцией."
  - В логах писать, была ли картинка реально отправлена в модель (на случай сбоев/лимитов).

    - какие — для мультимодала;
    - какие бесплатные/быстрые.

- **Единый стиль системных промптов**
  - Для OpenSCAD (CLI/GUI) и SolidPython2 (веб) использовать одинаковую логику:
    - жёстко требовать "только код";
    - всегда подчёркивать "parametric, commented, valid".

- **Тестовые сценарии**
  - Сделать небольшой набор "эталонных запросов" (benchmark prompts):
    - "корпус под электронику с крепёжными ушами";
    - "органическая рукоятка для инструмента";
    - "ваза высотой 150 мм с плавным профилем".
  - Проверять, как эти запросы отрабатывают в обоих интерфейсах и разных стратегиях.

## 5. UX / TODO: починить скроллинг в веб‑просмотрщике

Сейчас в `additive-light` колесо мыши на канвасе 3D‑просмотрщика обрабатывается через `wheel`‑обработчик с `preventDefault()`, из‑за чего:
- при наведении на viewer страница **перестаёт скроллиться вообще**;
- ощущается "липкий" UX, особенно на ноутбуках с тачпадами.

**Желаемое поведение:**
- когда курсор **над 3D‑просмотрщиком**:
  - колесо отвечает за **зум сцены** (OrbitControls);
  - но не ломает общую прокрутку страницы, если пользователь "перескроллил" границы (особенно на тачпадах);
- когда курсор **вне viewer**, страница должна скроллиться нормально.

**Идеи для реализации (следующие итерации):**
- Перестать вешать глобальный `preventDefault()` на `wheel` и:
  - полагаться на встроенный зум `OrbitControls`;
  - при необходимости ограничивать зум через `minDistance` / `maxDistance`, а не через блокировку события.
- Обернуть viewer в контейнер фиксированной высоты с `overflow: hidden`, но не блокировать колёсико полностью.
- Добавить опцию в настройках: "жёсткая привязка колеса к зуму" vs "мягкий режим" (для тех, кому привычно текущее поведение).
- В документации явно описать:
  - как именно должен работать зум;
  - какие известные ограничения есть для трекпадов/тачскролла.
