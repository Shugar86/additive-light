# 🏗️ Архитектурный проект: Generative Design Intelligence (GDI)

**Версия:** 1.0 (Март 2026)
**Парадигма:** Neurosymbolic AI («Слепой инженер» + Детерминированные щупы + Компилятор как Судья)
**Целевой пайплайн:** `Raw Mesh (STL) ➔ 2.7D Math ➔ YAML ➔ LLM ➔ Build123d (STEP) ➔ CAM (G-code)`

***

## 1. Базовый стек технологий (Core Stack)

Каждая библиотека выбрана для обхода известных "галлюцинаций" ИИ и ограничений 3D-пространства:

* **Оркестрация агентов:** `LangGraph` (управление состояниями графа, циклы while_loss > threshold).
* **LLM Engine:** `Claude 3.5 Sonnet` / `Qwen 2.5 Coder` / `GigaChat` (строго в текстовом режиме, без Vision).
* **Геометрическое ядро (CAD):** `build123d` (Python-обертка над `OpenCASCADE` / `OCP`). Выбрана вместо CadQuery из-за использования контекстных менеджеров (`with BuildPart():`), которые формируют идеальное абстрактное дерево для LLM и не теряют локальные переменные.
* **Математика и Сенсоры:** `Trimesh` / `Open3D` (работа с мешем), `SciPy.optimize` (сплайновая регрессия, RANSAC), `Shapely` / `OpenCV` (2D-контуры и IoU).
* **CAM \& ЧПУ:** `FreeCAD Path Workbench` (генерация G-кода через Python-API).
* **Изолированная среда (Sandbox):** `Modal` или Docker-контейнеры (для безопасного запуска динамических скриптов).

## 2. Граф Агентов (Pipeline Nodes)

### Шаг 0. Инициализация (Human-in-the-Loop)

* **Вход:** Грязный 3D-скан (STL) сломанной детали.
* **Действие:** Оператор кликает на базовую плоскость (Z=0) и ось центра (X, Y).
* **Результат:** Математически жестко зафиксированная система координат (нивелирует ошибку базирования на косых сканах).


### Узел 1. Sensor (Multi-axis Slicer)

* **Библиотеки:** `Trimesh`, `Shapely`.
* **Роль:** Декомпозиция 3D-хаоса в 2D-данные.
* **Алгоритм:** Шинкует выровненный STL по осям X, Y, Z с шагом 0.1 мм. Вычисляет для каждого среза параметры: площадь, центроид, bounding box. Определяет «Ось минимальной дисперсии» (базовую ось построения).


### Узел 2. Approximator (Vector Regression)

* **Библиотеки:** `SciPy` (least_squares, RANSAC).
* **Роль:** Восстановление разрушенных зон и сборка piecewise-функций (2.7D).
* **Алгоритм:** Анализирует эволюцию 2D-контуров вдоль оси Z. Если радиус не меняется — помечает зону как `Cylinder`. Если линейно падает — `Chamfer/Cone`. Выкидывает шум через RANSAC. Генерирует итоговый YAML-отчет.


### Узел 3. Synthesizer (LLM Orchestrator)

* **Роль:** Мозг системы. Принимает YAML от Аппроксиматора и генерирует параметрический код.
* **Синтаксис:** Строго `build123d`.


### Узел 4. Judge (Compiler \& Math Evaluator)

* **Роль:** Безвизуальная оценка геометрии.
* **Алгоритм 1 (Синтаксис и Топология):** Запускает код через ядро OpenCASCADE. Если возникает ошибка топологии (вывернутые нормали, самопересечения), использует `BRepCheck_Analyzer` для извлечения текстового лога ошибки и возвращает его Синтезатору.
* **Алгоритм 2 (Геометрия):** Слайсит сгенерированную STEP-модель и сравнивает ее 2D-контуры с оригинальным STL через Intersection over Union (IoU). Если совпадение < 98% — отправляет на доработку.


### Узел 5. Optimizer (Refactorer)

* **Роль:** Приведение сырого кода к инженерному стандарту.
* **Алгоритм:** Выделяет хардкод-значения в переменные (`HOLE_DIA = 12.0`), применяет Beautification (округление 11.98 мм ➔ 12.0 мм по ГОСТу/ISO).


### Узел 6. CAM Postprocessor

* **Библиотеки:** `FreeCAD Path`.
* **Роль:** Конвертация STEP в машинный код.
* **Алгоритм:** Берет готовую B-Rep модель, автоматически назначает фрезы, генерирует траектории (Toolpaths) и экспортирует `.nc` файл под конкретную стойку станка (Fanuc/Siemens).

## 3. Протокол коммуникации: Структура YAML и SCoT

Интерфейс между детерминированными "Щупами" (Python) и "Мозгом" (LLM) осуществляется через типизированный YAML. Этот формат навязывает модели Structured Chain-of-Thought (SCoT).

**Пример реального payload-промпта, который уходит в LLM:**

```yaml
# ---------------------------------------------------------
# GENERATIVE DESIGN INTELLIGENCE: SENSOR TELEMETRY
# ---------------------------------------------------------
Global_State:
  Target_Action: "Generate parametric B-Rep code"
  Target_Library: "build123d"
  Base_Axis: "Z"
  Total_Height: 45.0

# Данные от Аппроксиматора (Математически выверенные зоны)
Topological_Zones:
  - Zone_ID: 1
    Span_Z: [0.0, 15.0]
    Geometry: "Constant_Profile"
    Cross_Section: "Circle"
    Parameters: {Radius: 20.03, Center: [0.0, 0.0]}
    Sensor_Hint: "Stable RANSAC fit. Probably a base cylinder. Suggest beautification to 20.0."
    
  - Zone_ID: 2
    Span_Z: [15.0, 20.0]
    Geometry: "Linear_Regression"
    Cross_Section: "Circle"
    Parameters: {Radius_Start: 20.03, Radius_End: 15.01}
    Sensor_Hint: "Radius decreases linearly. Build as Chamfer or Loft."

  - Zone_ID: 3
    Span_Z: [20.0, 45.0]
    Geometry: "Constant_Profile_with_Holes"
    Cross_Section: "Circle"
    Parameters: {Outer_Radius: 15.01, Hole_Count: 4, Hole_Radius: 3.0}
    Sensor_Hint: "Detected 4 internal contours in polar array."

# ---------------------------------------------------------
# REASONING TASK (SCoT)
# ---------------------------------------------------------
# LLM MUST FILL THE THOUGHT_PROCESS BEFORE WRITING CODE
Agent_Task:
  Rules:
    - "Do not use visual assumptions. Rely ONLY on the Parameters above."
    - "Use 'with BuildPart():' and 'with BuildSketch():' context managers."
    - "Round floats to 1 decimal place (Beautification)."

  # ИНСТРУКЦИЯ: ИИ обязан заполнить комментарии для самопроверки
  Thought_Process: |
    # 1. Zone 1 (0 to 15): Create base cylinder R=20.0, H=15.0.
    # 2. Zone 2 (15 to 20): Apply chamfer of 5.0 to the top edge of Zone 1.
    # 3. Zone 3 (20 to 45): Extrude top face R=15.0 by 25.0.
    # 4. Holes: Select top face, create PolarArray(radius=..., count=4), cut holes.
  
  Code_Output: >
    from build123d import *
    # LLM writes the actual code here based on the Thought_Process
```

## 4. Архитектура Динамических Сенсоров (Dynamic Tool Making)

Если данных в базовом YAML не хватает для принятия решения (например, Сенсор фиксирует сложную кривизну, которую не берет 2.5D слайсер):

1. **Epistemic Uncertainty Trigger:** LLM понимает, что не может написать код без галлюцинаций.
2. **Tool Generation:** LLM пишет микро-скрипт (например: *"извлеки нормаль к поверхности в координате X=10, Y=5, Z=20"*).
3. **Sandbox Execution:** Оркестратор запускает этот скрипт в изолированном Docker-контейнере с доступом к исходному `STL` через библиотеку `Trimesh`.
4. **Feedback:** Песочница возвращает точный вектор `[0.707, 0, 0.707]`.
5. **Resolution:** LLM понимает, что это угол 45 градусов, и генерирует точный код `Build123d`.

## 5. Стратегия MVP (Ограничение Scope)

Для релиза пилота (для акселератора) система искусственно ограничивается **правилом Парето (80/20)**:

* **Поддерживаемые классы деталей:** Тела вращения (валы, фланцы) и 2.5D фрезеровка (плоские кронштейны).
* **Игнорируемые классы:** Органика, литые корпуса сложной формы, 5-осевые импеллеры (требуют NURBS-математики, что переносится в Roadmap на 2027 год).

**Ценностное предложение (Value Proposition) для питча:**
*"Платформа GDI принимает 3D-скан изношенной детали, детерминированно извлекает ее топологию без 'галлюцинаций' ИИ, генерирует редактируемый параметрический скрипт сборки и выдает готовый G-код для ЧПУ-станка. Время цикла сокращается с 3-5 дней до 15 минут".*
