# Как участвовать

Additive Light / GDI — исследовательский проект (R&D). Код открыт под MIT, и мы рады идеям, баг-репортам и PR, но из-за специфики проекта просим сначала обсудить крупные изменения.

## Быстрый путь

1. Форкни репозиторий.
2. Создай ветку: `git checkout -b feature/краткое-описание`.
3. Сделай изменения (минимальный diff, KISS).
4. Запусти тесты и линтеры:
   ```bash
   pytest tests/ -v
   black gdi_core/ gdi_app/ web/
   mypy gdi_core/
   ```
5. Открой PR с описанием: что сделано, зачем, как проверялось.

## Стиль

- Python: PEP 8, `black`, аннотации типов где это не усложняет.
- JS/CSS: придерживайся существующего стиля `script.js` / `style.css`.
- Коммиты: конкретные, на русском или английском (как основной язык задачи). Пример: `feat: добавить retry для OpenRouter`.
- Документация: если меняешь архитектуру или публичный API — обнови `README.md`, `ARCHITECTURE.md` или `CHANGELOG.md`.

## Что не надо коммитить

- `.env`, `*.pem`, `id_*`, токены, пароли.
- `node_modules/`, `__pycache__/`, `.venv/`.
- `openscad.wasm` (бинарный файл; см. `.gitignore`).
- Локальные артефакты: `output/`, `logs/`, `test_output/`.

## DoD для PR

- [ ] Код релевантен задаче.
- [ ] Тесты проходят (`pytest tests/ -v`), или добавлены новые.
- [ ] Код отформатирован (`black`).
- [ ] Секреты не утекли.
- [ ] Документация обновлена при необходимости.

## Обсудить до кода

- Крупные изменения архитектуры (например, замена OpenSCAD WASM, новый AI-провайдер).
- Изменения публичного API.
- Prod-деплой и работа с ключами.

Спасибо, что помогаешь делать генеративный CAD предсказуемее.
